# Install and set up Kalends

## What you need

- Hermes Desktop with **Capabilities → Plugins → Install from Git**, and a Hermes backend that supports unified plugins and plugin Agent settings.
- An Apple Account with iCloud Calendar and two-factor authentication turned on. The Hermes backend needs to be able to reach iCloud over HTTPS.

There's no verified minimum Hermes version yet. If those plugin controls are missing, update Hermes Desktop and the backend first. If you're coming from `icloud-caldav` 0.1.4, [back up your settings before upgrading](#before-upgrading-or-rolling-back).

## Install from Git

1. Open **Capabilities → Plugins → Install from Git** in Hermes Desktop. Paste `https://github.com/Anunnaki-Astronaut/kalends`.
2. If Hermes runs on your computer, choose both **Desktop** and **Agent**. If you use a remote Hermes backend, install **Desktop** on your computer and **Agent** for the profile on that backend. The Agent part connects to iCloud; installing only the sidebar won't connect your account.
3. Review the prompts, including any Python dependencies, then complete the install. Enable Kalends in Desktop and enable its Agent part for that backend profile. Look for **Kalends** in the sidebar. The Agent plugin ID is `icloud-caldav`.

For a pinned install, open the [commit list](https://github.com/Anunnaki-Astronaut/kalends/commits/main/) and copy the full 40-character SHA of the commit you reviewed. Paste it into **Pin to commit** if Desktop offers that field. You can also install the Agent part from a terminal on the backend. Replace `<full-commit-sha>` before running this command in the intended Hermes profile:

```bash
hermes plugins install https://github.com/Anunnaki-Astronaut/kalends --ref '<full-commit-sha>' --enable
```

## Connect and grant access

1. Go to [account.apple.com](https://account.apple.com/). Under **Sign-In and Security → App-Specific Passwords**, [generate a password for Kalends](https://support.apple.com/en-us/102654). Don't use your regular Apple Account password.
2. Open **Kalends** in Desktop and click the gear. Under **Accounts**, click **Set up iCloud account** or **Update Accounts**. In **Agent settings**, enter your Apple Account sign-in and the app-specific password, then save. Check that the settings are for the backend profile you meant to use. Never paste the password into a Hermes conversation.
3. Return to **Kalends Settings → Calendar access** and click **Test and discover calendars**. Seeing "credentials configured" is not the same as connecting successfully. Wait for the list of calendars.
4. New calendars start **Off**. Turn on **Read** for the ones you want, then click **Save calendar access**. Leave **Create**, **Edit**, and **Delete** off if you only want to see your events.
5. Click **Back to Calendar** and pick a date you know has an event. If it's missing, check that its calendar has **Read** and is visible in the view.

## Use the calendar

- In **Personal**, choose a date and read its agenda. Click an event for details. Use **Today**, the month arrows, or click the month heading to jump to a different month or year. When a date has keyboard focus, the arrow keys move between dates.
- Use the calendar checkboxes to hide calendars from the view. To stop the sidebar and Agent tools from reading one, turn off **Read** in **Calendar access** and save. **Discard unsaved changes** leaves your current permissions in place.
- The sidebar doesn't change events. To let Hermes Agent make a change, turn on the matching **Create**, **Edit**, or **Delete** permission for that calendar and save. Ask Hermes for the specific change, then check the calendar and event in the confirmation prompt before approving. Turning off **Read** also turns off writes. The tools don't change recurring events or invitations.
- The move tool requires **Read** on both calendars, **Delete** on the source, and **Create** on the destination. In this version it stops at a verified copy and never deletes the original.
- To change colors, open **Kalends Settings → Appearance**. **Match Desktop** follows Hermes; **System** follows your device. Choose **Light** or **Dark** to pick a mode yourself. Open **Theme Maker** to edit that palette, then click **Apply to Light** or **Apply to Dark**. This changes only Kalends on this device.

## Optional views

You can skip this section if you only want your iCloud calendar.

### Media

1. In **Kalends Settings → Special views**, click **Open Agent settings for media feeds**.
2. Paste the iCalendar link generated by Sonarr or Radarr into the matching field. Use an `https://` URL with a private IPv4 address that your Hermes backend can reach. A hostname, a public address, or a `webcal://` link won't work. For HTTPS, the backend must trust the certificate for that address.
3. Enable the matching Sonarr or Radarr feed and save. Return to **Special views** and click **Check media setup**. Go to **Media** in Kalends and choose **TV** or **Movies**. Kalends shows what the feed returns; switching months doesn't widen the feed's date range.

The link contains a credential. Don't share it. Plain HTTP requires a separate opt-in for each feed and sends the credential unencrypted, even on a private network.

### Automations

In **Kalends Settings → Special views**, click **Load automation checklist**. Select the jobs you want and click **Save automation selection**. Open **Automations** in Kalends to see the next scheduled run for each selected, enabled job in that Hermes profile. This view doesn't start jobs or show their run history.

### Forecast

In **Agent settings** for the selected backend, enter a Pirate Weather API key and the latitude and longitude you want the forecast for. Turn on **Enable optional forecast** and save. Return to **Personal** and check the **Forecast** for your selected day. Kalends uses the coordinates you enter, not your device location or event locations.

## Troubleshooting

| What you see | What to try |
| --- | --- |
| No Kalends sidebar entry | Enable **Desktop** for Kalends. If it still doesn't appear, run **Reload desktop plugins** from the command palette. |
| Plugin not found, or backend disconnected | Reconnect Hermes Desktop to the backend, then make sure **Agent** is installed and enabled for the selected profile. |
| Credentials configured, but discovery fails | Check the profile and the app-specific password, then make sure the backend can reach iCloud. Run **Test and discover calendars** again. |
| A discovered calendar doesn't show up in Personal | Turn on **Read**, click **Save calendar access**, and check that you haven't hidden the calendar. |
| Kalends says a month's results are incomplete | Check the affected dates in Apple Calendar before trusting the agenda. Some timed events with no duration are skipped; other unsupported events can interrupt a calendar read. |
| A media feed or forecast is unavailable | Check that its consent switch is on for the selected profile. Check the feed URL and certificate or the weather key and coordinates in **Agent settings**. Don't put those values in an issue. |

### One calendar keeps asking you to retry

If you find a timed event whose start and end match, fix the end time in Apple Calendar only if the event was meant to have a duration. Then click **Retry** for the calendar in Kalends. If the event is supposed to mark a single moment, leave it alone and use Apple Calendar to check it. You don't need to change sharing or grant **Edit** to troubleshoot a read.

## Disconnect

In **Kalends Settings → Calendar access**, click **Revoke calendar access**. This turns off the saved grants; it doesn't clear the credentials stored by Hermes. Clear the Apple Account sign-in and app-specific password in **Agent settings**, and [revoke the app-specific password at Apple](https://support.apple.com/en-us/102654) if you no longer use it. Turn off any optional feeds and clear their keys or URLs separately. If you're done with Kalends, disable **Desktop** and **Agent** in **Capabilities → Plugins**.

## Before upgrading or rolling back

Make a private backup of the existing plugin and its permissions in the selected backend profile before upgrading. Version 0.3.0 treats an old **Read and write** grant as **Read** and **Create** only. It doesn't add **Edit** or **Delete**. Review the grants before saving them. **Save calendar access** writes a format 0.1.4 can't read, so keep the old permissions backup if you might roll back.
